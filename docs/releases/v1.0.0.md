# v1.0.0 — Urdu-English Voice Interpreter

First public open-source release. A real-time Urdu → English voice interpreter
for macOS meetings.

## Overview

Speak Urdu into your microphone during a Google Meet, Zoom, or Microsoft Teams
call, and this app shows the live Urdu transcript with its English translation
and plays the translated English voice through your selected output device.
When BlackHole is installed, you can route the translated voice into the
meeting app as your virtual microphone.

## Highlights

- **Complete M1–M10 Phase 2 pipeline** — microphone capture, Urdu
  speech-to-text (`ur-IN`), Urdu → English translation, live subtitles, English
  TTS, and selectable audio output.
- **Azure production path** — Azure Speech → Azure Translator → Azure streaming
  TTS with incremental PCM playback for early audio.
- **Low-latency interpretation** — interim translations update live and are
  replaced by the authoritative final translation when it arrives.
- **Streaming TTS with preemption** — newer speech interrupts stale synthesis,
  with ordered chunk playback and a bounded FIFO queue.
- **BlackHole routing** — output the translated voice into the meeting app's
  virtual microphone.
- **Provider abstraction** — swap in deterministic Mock providers or macOS `say`
  for local development without cloud credentials.
- **Secure by default** — Electron preload bridge with `contextIsolation` and no
  `nodeIntegration`; credentials stay in `.env`.

## Requirements

- macOS (Apple Silicon supported).
- Node.js 18+ and npm.
- Azure Speech and Translator credentials for the production cloud path
  (STT, translation, and TTS keys).
- BlackHole 2ch for routing translated audio into a meeting app.

## Validation status

- `npm run type-check`, `npm run build`, and the 43-test automated suite pass.
- The M10 Phase 2 acoustic streaming benchmark is **pending/manual** — no
  end-to-end latency improvement is claimed yet.
- Full real Google Meet / Zoom / Microsoft Teams validation is **pending/manual**.

## Known limitations

- No authentication system, no backend service, and no database.
- No direct Google Meet / Zoom / Teams API integration — audio routing is device
  based.
- MyMemory is demo/fallback only and is aggressively rate-limited.
- Deepgram, OpenAI, and other providers are future/optional work.
- Real Azure speech, translation, and TTS quality require valid credentials.

## Future roadmap

- M10 Phase 3: production meeting-pipeline hardening and end-to-end validation
  of the streaming path.
- Full real meeting-app validation in Google Meet, Zoom, and Microsoft Teams.
- M10 Phase 2 acoustic streaming benchmark (manual).
- Future/optional provider integrations (e.g., Deepgram, OpenAI) behind the
  existing provider abstractions.
- Reverse-direction (English → Urdu) and additional language pairs.
