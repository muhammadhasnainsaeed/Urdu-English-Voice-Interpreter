# v1.1.0 — Urdu-English Voice Interpreter

Second release. A real-time Urdu → English voice interpreter for macOS meetings,
built on the v1.0.0 pipeline with a complete UI overhaul, first-run onboarding,
voice selection, and hardened production packaging.

## Added

- **First-run onboarding wizard** — one-time "Get Ready" setup that walks the
  user through microphone permission, the audio-output device, and BlackHole
  detection before ever entering the Home screen. Re-runnable at any time from
  Settings → Setup. Completion is persisted (`preferences.json`).
- **Focused Home + dedicated Settings page** — Meeting Mode, Speech to Text,
  and Translation on the Home screen; configuration moved to a sidebar Settings
  page (Audio, Voice, Appearance, Performance, Diagnostics, Setup).
- **Searchable voice picker** — Settings → Voice selects a text-to-speech voice
  (Azure Neural voices in production; macOS `say` system voices additionally in
  development). The choice persists across restarts. Voice routing was fixed so
  a macOS system voice is never sent to the Azure SDK.
- **ElevenLabs-styled microphone selector** — live waveform, device dropdown,
  and record / pause / play / trash sound-check controls on the Audio settings
  page.
- **Light / dark / system theme toggle.**
- **Centralized error handling** — every pipeline failure flows through a single
  normalize → classify → toast path; raw provider details never reach the user.
- **Packaged-app runtime configuration** — packaged builds read a user-owned
  `~/.urdu-english-interpreter/.env` (or shell environment) at runtime; the app
  never bundles credentials. Startup logs `[CONFIG]` diagnostics naming the exact
  file to edit.
- **Truthful configuration errors** — when a provider is not configured, the app
  says so and names the missing variables / exact file, instead of a generic
  failure message.

## Changed

- **Licensed under the GNU General Public License v3.0** (v1.0.0 was MIT).
- **UI migrated to shadcn/ui + Tailwind CSS v3** (previously custom CSS).
- **TTS voice selection end-to-end** — persisted voice id threads through the
  session manager into the Azure / `say` provider.
- **Production provider defaults** — packaged builds default to the real Azure
  providers (STT, translation, and TTS) when unset in the runtime config, so a
  base install never silently falls back to a mock provider.
- **Development tooling** — ESLint 9 (flat config) + Prettier, dependable
  Tailwind watch, and renderer hot reload during development.

## Fixed

- **Packaged-only translation regression** — packaged builds were selecting the
  mock translation provider (identity passthrough that returned the Urdu text
  prefixed `[English] `). Packaged builds now default `TRANSLATION_PROVIDER` to
  `azure`; verified in `package:dir` and the installed DMG.
- **Packaged-only TTS regression** — "Test Voice" was silent because the TTS
  provider defaulted to mock (200 ms of silence). Packaged builds now default
  `TTS_PROVIDER` to `azure`.
- **Misleading STT error toast** — missing STT credentials now produce an
  actionable "not configured" warning instead of "Speech recognition failed".
- **Pipeline telemetry panel regression** — the Performance panel's metrics were
  empty because the telemetry enabled-flag was captured before `dotenv` loaded;
  it now re-evaluates at call time.
- **Microphone sound-check quality** — record → stop → play → pause flow was
  distorted by overlapping waveform reads and a remounting waveform; both fixed.
- **Settings horizontal overflow** — long device labels no longer spill past the
  Settings content pane.

- `npm run type-check`, `npm run lint` (0 errors), `npm run format:check`, and
  `npm run build` all pass.
- Automated suite: **105 tests pass / 0 fail** (98 at v1.0.0). New coverage:
  runtime config loading, truthful STT/translation diagnostics, onboarding
  states, TTS voice provider/listing, error model, and the M11 UX surfaces.
- Packaged build (`npm run package:dir`) verified end-to-end: app launches,
  onboarding/setup works, Start/Stop Meeting works, Urdu STT recognizes, the
  translation card shows **actual English** (not mock identity output), TTS
  synthesizes real audio, subtitles update live, Settings has no overflow, the
  `PIPELINE_DEBUG` performance panel is only exposed when enabled, and the
  `~/.urdu-english-interpreter/.env` runtime config is honored.
- **Both development and packaged translation verified**: Urdu STT final →
  English translation in `npm run dev` and in the packaged `.app`.
- Real Google Meet / Zoom / Microsoft Teams validation remains pending / manual
  (device-based routing only; no meeting-app API integration).

## Requirements

- macOS (Apple Silicon / arm64). Node.js 18+ and npm for development.
- Azure Speech, Translator, and TTS credentials for the production cloud path.
- BlackHole 2ch for routing translated audio into a meeting app (optional for
  local use).
